# API

## Overview

The contract a client and a caller code against. A client that a person
uses lists connectors, connects one, confirms a sign-in, and
disconnects. A caller that has a token uses a connection through its
address. The contract is one OpenAPI 3.1 document in the public package
`api`, served by the binary and held to the Go types by a test.

## Current state

Built; see Implementation status.

## Design

### Conventions

All routes sit under a base path, `/v1` by default, set by
`PONS_BASE_PATH` so a deployment can mount the surface under a prefix
of its own. Every route below the base path needs a bearer token,
except four: `GET /callback`, which the other service returns a
person's browser to, `GET /client` and `GET /client/{id}`, the
documents that identify Pons to an authorization server, and
`GET /openapi.yaml`. The probes,
`GET /livez`, `GET /readyz` and `GET /version`, are those of
`latere.ai/x/pkg/health`, sit outside the base path and need no token
([[010-records-and-observability]]).

Bodies are JSON. A request with a member the contract does not describe
is `400 unknown_field`. A list pages by a cursor, `limit` 50 by default
and 200 at most, newest first by id, with `next_cursor` the last id of a
page; a caller treats the cursor as opaque. The envelope, the error
shape and the cursor are those of `latere.ai/x/pkg/httpjson` and
`latere.ai/x/pkg/pagination`.

A create takes `Idempotency-Key`. The same key from the same subject
within 24 hours answers the first response again and creates nothing.
The one exception is a connection made by signing in: a repeat answers
the same connection with a new `authorization_url`, whose flow replaces
the first, since Pons keeps no copy of the address it handed out.

### Routes

| Method and path | Purpose | Answers | Action asked |
|---|---|---|---|
| `GET /connectors` | the catalog and the connectors the caller added; `kind`, `limit`, `cursor` | 200, 403 | `connector.list` |
| `GET /connectors/{ref}` | one connector, by catalog name or id | 200, 404 | `connector.read` |
| `POST /connectors` | add a connector by its address | 201, 400, 403, 422, 429 | `connector.create` |
| `DELETE /connectors/{id}` | remove a connector the caller added, when no connection uses it | 204, 404, 409 | `connector.delete` |
| `POST /connections` | connect a connector | 201, 400, 403, 404, 409, 422, 429 | `connection.create` |
| `GET /connections` | the connections the caller may see; `owner`, `connector`, `state`, `limit`, `cursor` | 200, 403 | `connection.list` |
| `GET /connections/{id}` | one connection | 200, 404 | `connection.read` |
| `PATCH /connections/{id}` | rename | 200, 400, 404, 409 | `connection.update` |
| `POST /connections/{id}/confirm` | finish a sign-in with the code the browser brought back | 200, 400, 404, 409, 410 | `connection.create` |
| `POST /connections/{id}/reconnect` | start a new sign-in for an existing connection | 200, 400, 404, 409, 422, 429 | `connection.create` |
| `PUT /connections/{id}/credential` | replace the key of a `token` connection, or the client of a `client_credentials` one | 204, 400, 404, 409, 422 | `connection.create` |
| `DELETE /connections/{id}` | disconnect | 204, 404 | `connection.delete` |
| `GET /connections/{id}/calls` | the connection's call records; `limit`, `cursor` | 200, 404 | `connection.read` |
| any method, `/connections/{id}/http/{path}` | the forwarding address of a connection of kind `http` ([[014-http-forwarding]]) | the connector's own, or an error below | `connection.use` |
| `GET` and `POST /connections/{id}/git/{path}` | the git address of a connection of kind `http` whose connector names `git.url`: git's smart HTTP alone ([[014-http-forwarding]]) | the connector's own, or an error below | `connection.use` |
| `POST /connections/{id}/mcp` | the connection's address for a connector of kind `mcp`; `GET` and `DELETE` too, for a connector on a protocol revision that has them ([[008-carrying-a-call]]) | the connector's own, or an error below | `connection.use` |
| `GET /callback` | where the other service returns a person's browser | 302, 400 | none |
| `GET /client` | Pons's client metadata document, for catalog connectors | 200 | none |
| `GET /client/{id}` | the client metadata document of a connector a person added | 200, 404 | none |
| `GET /openapi.yaml` | this contract | 200 | none |

A route about a stored object answers a deny the way it answers a
missing object, with the `404` of its kind, so an id cannot be probed
for what somebody else owns ([[004-identity-and-authorization]]).

### Adding a connector

```json
POST /connectors
{ "name": "team-wiki", "title": "Team wiki", "kind": "mcp",
  "url": "https://wiki.example.com/mcp", "auth": { "type": "oauth" } }
```

`auth.type` is `oauth`, `token` or `none`. For `oauth` Pons reads how
the server signs people in before it answers. A server it cannot read
is `422 connector_unreachable`. One that offers no way for Pons to
identify itself, or whose metadata does not set
`authorization_response_iss_parameter_supported` to `true`, is `422
sign_in_unsupported` ([[007-sign-in]], [[006-catalog]]). For `token`
the request may give `auth.inject`. The answer is the connector with
its `id`. An added connector is its owner's alone and takes no
`hosts`: its credential goes to the host of its `url` alone
([[006-catalog]]). Its `url` passes the rules of
[[009-outbound-requests]], or the request is `400 invalid_field`.

### Connecting

```json
POST /connections
{ "connector": "notion", "name": "notion", "owner": "",
  "return_to": "https://chat.example.com/settings/connectors" }
```

| Member | Rule |
|---|---|
| `connector` | a connector reference; required |
| `name` | optional; the connector's name by default; `409 name_taken` when the owner holds one of that name |
| `owner` | optional; the owner the caller asks to connect for. The authorizer decides whether it may, and its allow says whose the connection is |
| `return_to` | required for `oauth`: where the browser goes after the sign-in. It must be an entry of `PONS_RETURN_URLS`, or lie under an entry that ends in `/` ([[007-sign-in]]), or the request is `400 invalid_field` |
| `credential.value` | required for `token`: the key. Write-only |
| `credential.client_id`, `credential.client_secret` | required for `client_credentials` |
| `scopes` | optional, for `oauth`: scopes to ask for beyond what the server names |

For `oauth` the answer is `201` with the connection in `pending` and
one member beside it:

```json
{ "connection": { "id": "con_01jb…", "state": "pending", "…": "…" },
  "authorization_url": "https://auth.example.net/authorize?…" }
```

The client keeps the connection's id in the person's own session and
sends the person's browser to `authorization_url`. For `token`,
`client_credentials` and `none` the answer is `201` with the connection
`connected`. A key is tried once against the connector before it is
kept, by listing its tools, and a key the connector refuses is `422
credential_refused` and nothing is stored.

### The callback and the confirm

`GET /callback?code=…&state=…` is the redirect address Pons gives every
authorization server. It finds the flow by `state`, validates the
answer, exchanges the code and seals the tokens with the flow
([[007-sign-in]]). It then answers `302` to the flow's `return_to` with
two query members added: `connection`, the connection's id, and either
`code`, a one-time code good for 2 minutes, or `error`, one of
`access_denied`, `sign_in_failed` and `flow_expired`. A `state` that
matches no live flow is `400` with a page that says the link has
expired, and no redirect.

```json
POST /connections/{id}/confirm
{ "code": "…" }
```

The client calls it for the person whose session started the
connection, after checking that the `connection` the browser brought
back is the one that session started. Pons asks `connection.create`
for the connection's owner, compares the code, and moves the tokens
from the flow to the connection. The answer is the connection,
`connected`. A wrong code is `400 invalid_code` and spends the flow. A
flow whose time has passed is `410 flow_expired`.

`POST /connections/{id}/reconnect` takes `return_to`, held to the same
rule, and optional `scopes`. It answers `200` with the body a create of
kind `oauth` answers: the connection, now `pending`, and
`authorization_url`. The connection keeps its id, its name and, until
the confirm, its old credential. A reconnect whose discovery finds
another issuer than the connection's is `422 sign_in_unsupported` with
`details.reason` `issuer_changed` ([[007-sign-in]]).

### Using a connection

`{base}/connections/{id}/mcp` is a Model Context Protocol server over
streamable HTTP, and it is the `address` a connection carries. A caller
sends what it would send the connector, with its own bearer token in
`Authorization`. What Pons does with the request, which headers pass
and how the answer streams are [[008-carrying-a-call]]'s. An error Pons
itself raises there has the shape below, and a status the connector
answered is passed on as it is.

### Errors

```json
{ "error": { "code": "connection_not_connected", "message": "This connection needs to be connected again.", "details": { "reason": "refresh_refused", "retryable": false, "state": "needs_reconnect" } } }
```

One code to branch on, one fixed sentence for a person in `message`,
and `details` for a developer: `reason` says what happened in this
instance, `retryable` whether the same request may succeed later, and
`field` which member of the request the error is about. An error nobody
classified is `500 internal` with no reason: its text is logged and not
returned. No error carries any part of a token or a credential.

| Status | Codes |
|---|---|
| 400 | `invalid_request`, `unknown_field`, `invalid_field`, `missing_field`, `invalid_code` |
| 401 | `missing_token`, `invalid_token` |
| 403 | `forbidden` |
| 404 | `connector_not_found`, `connection_not_found` |
| 409 | `name_taken`, `connector_in_use`, `connection_not_connected`, `wrong_kind` |
| 410 | `flow_expired` |
| 413 | `request_too_large` |
| 422 | `connector_unreachable`, `sign_in_unsupported`, `credential_refused` |
| 429 | `rate_limited` |
| 500 | `internal` |
| 502 | `connector_unavailable` |
| 503 | `authorizer_unavailable`, `sealing_unavailable` |
| 504 | `connector_timeout` |

`connection_not_connected` is what a caller that speaks for a person
branches on. Its `details.state` is the connection's state, and its
`details.reason` is one word: the connection's own reason when it has
one, `not_confirmed` when it is `pending` without one,
`connector_removed` when its connector left the catalog
([[006-catalog]]), and `scope_insufficient` when the connector asked for
more scopes, with `details.scopes` naming them
([[008-carrying-a-call]]). In each case the caller offers the person to
connect or reconnect. `wrong_kind` answers a request to an address the
connection's kind does not have, and a replaced credential its `auth`
does not take.

## Implementation status

Built and served, with `GET /openapi.yaml` describing exactly these:
`GET`, `POST /connectors`, `GET /connectors/{ref}`,
`DELETE /connectors/{id}`, `POST`, `GET /connections`,
`GET`, `PATCH`, `DELETE /connections/{id}`,
`PUT /connections/{id}/credential`, `GET /connections/{id}/calls`, the
MCP address of [[008-carrying-a-call]], and the forwarding and git
addresses of [[014-http-forwarding]], with the
error table, `Idempotency-Key` on both creates, the cursor, and the
probes of `latere.ai/x/pkg/health`. OpenAPI holds one path for two
templates of one shape, so the document writes `DELETE /connectors/{id}`
as `DELETE /connectors/{ref}`, described as the id of an added connector.
OpenAPI names no route of every method, so the forwarding address is
written with each method it names but `TRACE`, and the path below an
address as one parameter, `{path}`, that may hold slashes. The addresses
are served before the router, which would clean a path's dot segments
and decode its escapes before they could be refused.

The callback, the confirm, the reconnect and the client metadata
documents are served ([[007-sign-in]]); a connect of a catalog connector
whose people sign in answers the connection, `pending`, with
`authorization_url`.

A key is probed before it is kept, by a `tools/list` for kind `mcp`
([[008-carrying-a-call]]) and a `GET` for kind `http`
([[014-http-forwarding]]), and a client of `client_credentials` is
minted for once; a refusal is `422 credential_refused` with nothing
stored.

Remains: a connector a person adds of `auth.type` `oauth`. Its
discovery's first request, the probe's `tools/list`, is built
([[007-sign-in]]), but the add that checks its server's metadata and
the connect and reconnect of one are not, so `POST /connectors` of one
answers `422 sign_in_unsupported` with `details.reason`
`sign_in_not_available`. An added connector is held to port 443, which
no stub listens on, so its sign-in has no end-to-end test yet either.

## Acceptance criteria

| Criterion | Test that proves it |
|---|---|
| The served `openapi.yaml` describes every route of the table and no other, and every request and response of the handlers validates against it | `api.TestDocumentMatchesTheRoutes`, `httpapi.TestHandlersHoldTheContract` |
| Every route below the base path but the four named answers `401 missing_token` without a bearer, and the surface moves whole under `PONS_BASE_PATH` | `httpapi.TestRoutesNeedABearer`, `httpapi.TestBasePath` |
| A create with `auth.type` `oauth` answers `pending` with an `authorization_url`; with a key it answers `connected` after one probe, and a refused key stores nothing | `TestCreateBySignIn`, `TestCreateByKey` |
| A `return_to` that is not a configured URL and lies under no configured prefix is refused, and the callback redirects to no other address than the flow's | `TestReturnToIsHeldToItsURLs` |
| The confirm with the right code connects once; a second confirm, a wrong code and a late one are refused, and a wrong code spends the flow | `TestConfirmIsOnceAndTimed` |
| A read, a change and a use of a connection the caller may not see answer `404 connection_not_found`, and a create or a list the caller may not make answers `403` | `TestADenyDoesNotConfirmAnId` |
| The same `Idempotency-Key` from one subject answers the first response and creates one object | `TestIdempotentCreate` |
| Every error has a code of the table, the fixed sentence of its code, and no token or credential in any member | `httpapi.TestErrorTable`, `TestNoCredentialLeavesButTowardItsConnector` |
